# Каникулы в Аксаково — backend

Symfony 7 + API Platform 4 + EasyAdmin 4. Бэкенд информационного киоска и мобильной карты.

## Основные API

- `GET /api/home` — логотип, настройки главного экрана, погода и активный режим ожидания.
- `GET /api/changes?since={version}` — проверка изменений контента для обновления фронта.
- `GET /api/sections` — каталог 16 фиксированных клиентских разделов.
- `GET /api/sections/{slug}` — готовая структура конкретного экрана: `guest-info`, `service-hours`, `meal-times`, `connect`, `public-transport`, `medical-center`, `residence-rules` и другие.
- `GET /api/content_pages?type=...` — статичные разделы: о санатории, информация для гостей, «Подключайся», правила, Таганрог.
- `GET /api/content_items?section=...` — документы, расписания, постеры, инфраструктура, медицина, галерея, прайсы и памятки.
- `GET /api/section_documents?section=...` — универсальные PNG/JPG/PDF разделов; поддерживает вложенность «категория → файлы».
- `GET /api/map_plans`, `/api/map_nodes`, `/api/map_edges`, `/api/map_places` — карта и маршрутная сеть.
- `GET /api/map/search?q=...&plan=...` — поиск объектов без внешнего поискового сервиса.
- `POST /api/navigation/routes` — маршрут от терминала, узла либо GPS-координат телефона.
- `GET /api/navigation/qr/{placeId}` — QR мобильной карты с выбранной целью.
- `GET /api/content-items/{id}/qr` — QR для редактируемой внешней ссылки.
- `GET /api/weather/current` — стабильный DTO погоды.
- `POST /api/terminals/{code}/ping` — отметка активности терминала.
- `GET /api/settings/exit-password` — получение настраиваемого пароля для выхода из приложения.
- `GET|PUT|DELETE /api/map_plans/{planId}/geo_calibration` — версия и контрольные точки геокалибровки схемы.
- `POST /api/map_plans/{planId}/geo_calibration/preview` — кусочно-аффинный preview координат без изменения базы.
- `POST /api/map_plans/{planId}/geo_calibration/apply` — транзакционное применение сохранённой версии ко всем узлам.

Пример GPS-маршрута:

```json
{
  "destinationPlaceId": 12,
  "latitude": 56.0344,
  "longitude": 37.6029,
  "accessible": false
}
```

Координаты телефона проецируются на ближайший сегмент маршрутной сети. В ответе приходят исходная и привязанная позиции, расстояние привязки, полилиния карты, длина пути, мобильная ссылка и QR. При движении телефон повторяет запрос, поэтому маршрут пересчитывается динамически.

## Модель контента

### Проверка обновлений на фронте

`GET /api/changes` возвращает `{"version":"9c0bd25b5aa6416a9aad8556276883af","changed":true,"updatedAt":"2026-09-14T12:00:00+00:00"}`.
Версия — непрозрачная строка: сравнивайте на равенство, не сортируйте. `updatedAt` — время записи версии в UTC, не ключ для сравнения.

При первом запуске запросите версию, загрузите данные и сохраните полученную **до загрузки** версию только после успешной загрузки всех данных. Затем опрашивайте `/api/changes?since={version}` примерно раз в 30 секунд. `changed=false` означает, что обновление не требуется. При `changed=true` перезагрузите данные и сохраните `version` из ответа проверки после успешной загрузки. При ошибке оставьте прежнюю версию и повторите позже. Выполняйте проверки последовательно, чтобы ответы не перезаписывали друг друга. После перезапуска с пустым локальным кэшем не передавайте старую версию.

Версия записывается в одной транзакции с изменениями Doctrine: добавление, редактирование, удаление, сортировка, фотографии, настройки, карта и геокалибровка. Проверка читает одну строку БД и отдаёт `Cache-Control: no-store`. Без `since` всегда возвращается `changed=true`; некорректный формат `since` даёт HTTP 400.

Изменения пользователей и сигналы активности терминалов (`lastSeenAt`) не меняют версию. Погода обновляется отдельно. Прямые SQL-запросы, DQL bulk-операции и замена файлов вне приложения не отслеживаются. Перед запуском обновлённого приложения примените миграцию `Version20260914120000`.

Изображения и видео контентных карточек загружаются сущностью `MediaAsset` через VichUploaderBundle. PDF и изображения полноэкранных разделов загружаются прямо в форме конкретного экрана через VichUploaderField, без предварительного создания медиафайла.

`ContentItem.section` соответствует разделам ТЗ. Для иерархий используется `parentId`: категория прайсов → прайсы, медицинское отделение → услуги. Расписания имеют отдельные поля `times`, `weekdaysTimes`, `weekendsTimes`, `workingDays`, `startsAt`, `endsAt`, `breakStartsAt`, `breakEndsAt`, `roundTheClock`.

`SectionDocument` является внутренним общим хранилищем файлов экранов. В админке общей таблицы нет: БПЛА, инфраструктура, питание и полный график служб открывают сразу форму единственного файла; документы гостей, правила и шесть фиксированных категорий стоимости имеют собственные списки. В `GET /api/sections/{slug}` файлы возвращаются в `data.documents`, а специализированные данные раздела остаются рядом.

Для жилого объекта карты доступны `buildingNumber`, `floorCount`, `roomCount` и свой независимый набор категорий номеров. Категории создаются прямо в карточке корпуса; каждая содержит название, описание, порядок и собственный упорядоченный Vich-слайдер. Валидация и серверная очистка не дают сохранить поля корпуса у инфраструктурного объекта.

В админке жилые корпуса и инфраструктурные объекты имеют отдельные списки. В общей форме смена типа скрывает и очищает неподходящие поля. Технический узел маршрута не выбирается вручную: редактор задаёт понятные X/Y и GPS-координаты объекта, а бэкенд создаёт привязку и соединяет новый объект с ближайшим узлом графа. У каждого объекта есть собственная иконка и упорядоченная коллекция `photos`; все файлы загружаются прямо в форме объекта через VichUploaderField.

## Погода

По умолчанию используется бесплатный MET Norway Locationforecast 2.0, разрешающий коммерческое использование с атрибуцией. Обязателен идентифицирующий `WEATHER_USER_AGENT`. Результат кэшируется, при кратком сбое отдаётся последний успешный прогноз с `stale: true`.

`WEATHER_PROVIDER=open_meteo` оставлен для прототипирования; бесплатный публичный Open-Meteo не лицензирован для коммерческого использования.

## Запуск

```bash
composer install
php bin/console doctrine:migrations:migrate --no-interaction
php bin/console app:bootstrap admin 'change-me'
php bin/console app:seed-content
php tests/api-smoke.php http://holidays.local
```

`app:seed-content` идемпотентно добавляет отсутствующие страницы, расписания, документы, инфраструктуру, медицинские услуги, категории прайсов, жилые корпуса и тестовую маршрутную сеть. Опция `--refresh` обновляет стартовые записи. Включённые SVG-файлы предназначены для проверки API и должны быть заменены утверждёнными материалами через VichUploader в админке.

Локальный домен OSPanel: `http://holidays.local`. Админка: `/admin`, документация API: `/api`.

Prod-секреты задаются только в `.env.local`: `APP_ENV`, `APP_SECRET`, `DATABASE_URL`, `MOBILE_MAP_URL`, `WEATHER_PROVIDER`, `WEATHER_USER_AGENT`.
